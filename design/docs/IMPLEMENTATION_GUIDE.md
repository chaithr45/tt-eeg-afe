# Implementation guide: from these files to a Tiny Tapeout submission

Deadline: TTSKY26d closes **30 November 2026**. Work in this order; each step has a "done when" check so you know you can move on. Times are for someone doing this for the first time, a few hours per day.

```
Step 0  Tools (1 day)            → sim/run_all.py reproduces results/summary.json
Step 1  Schematics (2–3 days)    → you can netlist and simulate from the Xschem GUI
Step 2  Verification (3–4 days)  → Monte Carlo + real passives + PSRR documented
Step 3  Tiny Tapeout repo (1 day)→ template repo builds with the stub, pins fixed
Step 4  Layout                   → DRC clean, LVS clean, fits 160 × 225 µm          (done)
Step 5  Post-layout              → extracted netlist meets spec at tt/ss/ff/sf/fs   (done)
Step 6  Submit (1 day)           → GitHub Action green (done), submitted on app.tinytapeout.com
```

---

## Step 0 — Tools and reproducing the results

1. Install IIC-OSIC-TOOLS (Xschem, ngspice, Magic, KLayout, Netgen, SKY130 PDK, all pre-configured).
   - Windows PowerShell as Administrator: `powershell -c "irm https://osic.tools/install.ps1 | iex"` (installs WSL2 + Docker Desktop; reboot if asked).
   - Start with `start_vnc.bat`, open `http://localhost/?password=abc123` in a browser.
2. Copy the `eeg_frontend` folder into `%USERPROFILE%\eda\designs` (= `/foss/designs` inside the container).
3. In the container terminal:
   ```
   sak-pdk sky130A
   cd /foss/designs/eeg_frontend/sim
   python3 run_all.py --quick         # ~3 min, writes results/summary.json
   ```
   **Done when:** gain ≈ 37.8 dB, noise ≈ 2.9 µVrms, IDD ≈ 15.7 µA (same as `results/summary.json`).

**Two model sets.** The PDK ships two SKY130 model libraries, and the design is checked on both:
- `libs.tech/ngspice` — the original binned models. `run_all.py` uses these by default.
- `libs.tech/combined` — the newer "continuous" models. Xschem's SKY130 setup uses these, so the GUI testbench runs on them.
  Run the scripts on them with `SKY130_LIB=combined python3 run_all.py --quick` (results go to `results/summary_combined.json`).

The xhigh_po resistor is 28 % higher in the continuous models (RS = 118 kΩ instead of 92 kΩ), so the bias current is 0.39 µA instead of 0.50 µA, and IDD is 12.2 µA instead of 15.7 µA. Gain is the same (it is set by C1/C2), and all specs pass on both. Treat the spread as model uncertainty: silicon will land somewhere in between or outside, which is one more thing to measure.

`spice.py` finds the PDK through `$PDK_ROOT` (set by `sak-pdk`). It simulates the Xschem-generated netlist in `xschem/netlist/eeg_afe_top.spice`. `sim/compare_designs.py` shows it matches the original hand-written netlists in `sim/reference/` within 0.3 %.

## Step 1 — Schematics in Xschem

The schematics are generated by `xschem/gen_schematics.py` (net labels on every pin, so connectivity is correct by construction). Open them to read, annotate and edit; pictures are in `xschem/img/`.

```
cd /foss/designs/eeg_frontend/xschem
xschem tb_eeg_afe.sch        # testbench; the design is XTOP → eeg_afe_top → bias, afe → ota, pseudo_r
```

- Descend into a block: select the symbol, press **e** (Ctrl-e to go back up).
- Edit a device: select, press **q** (W, L, mult). MOS sizes stay inside the model bins: finger W ≤ 7 µm, L ≤ 20 µm.
- Simulate: **Netlist** (shift-N) then **Simulate**. The testbench runs power-up, a 10 ms reset pulse and a 100 µV / 10 Hz tone for 250 ms; it takes about 3 minutes and prints `gain` (expect 77 V/V), `vref_dc` (0.45 V) and `iddq` (−15.7 µA). Waveforms: the ngspice window plots `v(pad)`, or load `tb_eeg_afe.raw` with **Waves → Load**.
- Corner: edit the `CORNER` instance (`tt`, `ss`, `ff`, `sf`, `fs`); temperature: `.temp` in the `CONTROL` block.
- MIM capacitors: the testbench sets `MIM_MODEL` to an ideal capacitor fitted to the PDK model (<0.1 % error) because the PDK model's milliohm series resistors make the 10¹³ Ω nodes slow (12 min instead of 3 s for 60 ms). When `eeg_afe_top.sch` is netlisted as the top (for LVS), the real `sky130_fd_pr__cap_mim_m3_1` is used automatically.
- If you change a size in the GUI, re-run `sim/run_all.py` with the new netlist: **Netlist** on `eeg_afe_top.sch` with *Simulation → LVS netlist: top-level is a .subckt* ticked (or `python3 ../sim/compare_designs.py`, which netlists in batch mode).
- Re-generating from the script overwrites the `.sch` files, so once you start editing in the GUI, keep editing in the GUI (or edit the script and regenerate; don't mix).

**Done when:** you can run the testbench from the GUI and explain every device size (sheet 4 of `docs/EEG_front_end_schematic_v1.pdf`, `docs/sizes_table.py`).

## Step 2 — Verification to finish before layout

Each of these is a small testbench; copy `sim/tb_ac.py` / `tb_tran.py` and change the body.

1. **Monte Carlo mismatch**: `python3 tb_mc.py` (≈ 2–5 min; `python3 tb_mc.py 50` for a quick look). It runs 200 samples at tt/27 °C/1.8 V and 100 at the worst headroom corner (ss/0 °C/1.71 V) on the continuous models, and writes `results/montecarlo.json` and `results/fig4_montecarlo.png`. Expected: gain 77.70 V/V with σ ≈ 0.04 V/V, output DC offset −0.2 ± 0.3 mV, VREF σ ≈ 3 mV, unit current σ ≈ 4 %, M5 margin ≥ 0.07 V.
2. **Real passives:** Rz is already `res_xhigh_po_0p35`; check CREF and Cc with the PDK MIM model in AC (fast; only transient is slow).
3. **PSRR** vs frequency with the real bias (already in `tb_ac.py` → `frontend_ac(bias='real')`).
4. **Start-up** of the bias generator from a supply ramp, all corners: `python3 tb_startup.py` (and again with `SKY130_LIB=combined`). An operating-point run cannot show a start-up failure, only a transient can.
5. **Temperature limit, 50 °C** (README §5): if you want to push it higher, replace SW1/SW2 and S1–S3 with T-switches (two series NMOS with the middle node held at VREF when off) and re-run `corners.py`.
6. Keep the numbers in `results/` up to date; they go into `tinytapeout/docs/info.md`.

**Done when:** `results/corners.json`, `results/corners_combined.json` and a Monte Carlo table are regenerated with the final sizes, on both model sets. Freeze the schematic (tag it `v1-final` in git).

## Step 3 — Tiny Tapeout repository

Everything for the repository is prepared in the `tt-eeg-afe` folder: the Tiny Tapeout files (`info.yaml`, `src/project.v`, `docs/info.md` with a gain plot), a front-page `README.md`, and the whole design under `design/`. `info.yaml` and `docs/info.md` pass the Tiny Tapeout docs check (`tt_tool.py --check-docs`).

1. Put the folder in the container: save `tt-eeg-afe.zip` in `C:\Users\chait\eda\designs\`, then in the Linux terminal `cd /foss/designs && unzip -o tt-eeg-afe.zip`. From now on `tt-eeg-afe/design/` is the working copy of the design (the old `eeg_frontend` folder is only an archive).
2. Make the first (empty) layout, which checks the whole Tiny Tapeout flow before the real layout work. It draws the 161 × 225.76 µm tile with the template pins and the `VDPWR`/`VGND` met4 stripes, and writes `gds/` and `lef/`:
   ```
   sak-pdk sky130A
   cd /foss/designs/tt-eeg-afe/mag
   magic -dnull -noconsole -rcfile $PDK_ROOT/sky130A/libs.tech/magic/sky130A.magicrc magic_init_project.tcl
   ls ../gds ../lef
   ```
3. Sign in to github.com (a free account is enough). Open `github.com/TinyTapeout/ttsky-analog-template`, click **Use this template → Create a new repository**, name it `tt-eeg-afe`, set it to **Public**, and create it.
4. In the new repository: **Settings → Pages → Build and deployment → Source: GitHub Actions** (the `viewer` job needs it).
5. On the repository page: **Add file → Upload files**, then from `C:\Users\chait\eda\designs\tt-eeg-afe` drag in everything (`info.yaml`, `README.md`, `src`, `docs`, `design`, `mag`, `gds`, `lef`), then **Commit changes**. This replaces the template's `info.yaml`, `README.md`, `src/project.v` and `docs/info.md`.
6. Open the **Actions** tab and wait for both workflows. Expected: `docs` passes. `gds` builds and runs the precheck on the empty tile; if the precheck complains about the empty layout (for example unconnected outputs), that is expected at this point and is fixed by the real layout.

The repository is now at github.com/chaithr45/tt-eeg-afe and is the master copy. To get the latest version into the container:
```
cd /foss/designs
git clone https://github.com/chaithr45/tt-eeg-afe.git     # first time
cd tt-eeg-afe && git pull                                # afterwards
```

The top module is `tt_um_saichaithr_eeg_afe`. To use another name (for example with your GitHub username), change it in two places, `info.yaml` (`top_module`) and `src/project.v` (`module ...`), before starting the layout: the GDS, LEF and Magic cell must use the same name.

Analog rules to keep in mind (tinytapeout.com/specs/analog): 1x2 tile ≈ 160 × 225 µm; power on vertical `met4` stripes `VDPWR`/`VGND` (≥ 1.2 µm wide, from the bottom 10 µm to the top 10 µm); **no `met5`**; pins from the template DEF (`tt-support-tools/tech/sky130A/def/analog/tt_analog_1x2.def`), never moved; each analog pin path < 500 Ω, < 5 pF, < 4 mA; tie unused `uo_out`, `uio_out`, `uio_oe` to `VGND`. Cost: 1x2 tile 2 × 70 € + 2 analog pins × 40 € = 220 €.

**Done when:** the repository exists, `docs` is green and the `gds` workflow runs.

## Step 4 — Layout (done: scripted Magic flow)

The layout is generated by Python scripts in `layout/` that drive Magic; nothing is drawn by hand, so every change is reproducible and reviewable. To rebuild and check everything from scratch (about 5 minutes):

```
sak-pdk sky130A
cd /foss/designs/tt-eeg-afe/layout
python3 build.py
```

Expected output: every block `DRC 0`, `LVS OK` for pseudo_r, bias, the core and the Tiny Tapeout cell, then the parasitic extraction. To look at it: `magic -rcfile $PDK_ROOT/sky130A/libs.tech/magic/sky130A.magicrc ../mag/tt_um_saichaithr_eeg_afe.mag` (press **x** to expand a cell, **Shift-x** to collapse), or open `gds/tt_um_saichaithr_eeg_afe.gds` in KLayout. A picture is in `docs/layout.png`.

How it works (`layout/lay.py`): the SKY130 device generator draws each transistor, resistor and MIM capacitor as its own cell with guard rings (`devices.py`); the block scripts read where each terminal's metal is and write Magic commands that place the devices and draw the wires. Each block is checked on its own (DRC, LVS), then the core, then the tile.

| Script | Contents |
|---|---|
| `blk_pseudo_r.py` | two back-to-back PMOS pairs (each in its own n-well, bulk tied to source) and the three reset NMOS |
| `blk_ota.py` | input pair as ten rows of 6-finger 5/8 µm PMOS in the order A B B A A B A B B A (common centroid), mirror stacks, M5/M7, M6, Rz |
| `blk_bias.py` | beta-multiplier, start-up stack (6 × 0.6/20 µm), VREF diode |
| `blk_core.py` | the whole front-end in tile coordinates: blocks on the left, C1 / C1′ (3 × 3 MIM arrays) and Cc on the right, CREF bottom left, metal3 trunks in the gutter |
| `blk_top.py` | Tiny Tapeout cell from the template DEF: VDPWR/VGND met4 stripes, unused outputs tied to VGND, GDS and LEF |
| `lvs_core.py`, `lvs_top.py` | LVS of the core and of the whole cell against the Xschem netlist |

Rules learned on the way (they are in the scripts as comments): MIM top plate = `c0` = capm/met4, bottom plate = `c1` = met3, and the bottom plate goes on the low-impedance node; unrelated metal3 must stay 1.34 µm from capm (rule capm.11), so MIM plates are reached with metal4 bars; the xhigh_po resistors need a widened URPM mask hint (rule rpm.1); n-wells of the same net are painted as one well to avoid well-spacing errors.

**Done:** DRC clean in Magic and in the Tiny Tapeout KLayout decks, Netgen reports "Circuits match uniquely" for the core and for the tile, pins untouched.

## Step 5 — Extraction and post-layout simulation (done)

`build.py` ends with the parasitic extraction (`mag/eeg_afe_core_pex.spice`). `design/sim/tb_postlayout.py` simulates it next to the schematic in the same test environment, both with the on-chip bias:

```
cd /foss/designs/tt-eeg-afe/design/sim
python3 tb_postlayout.py                      # tt / 27 C: gain, band, noise, IDD, PSRR at 50 Hz
python3 tb_postlayout.py --corners --reset --tran
SKY130_LIB=combined python3 tb_postlayout.py --corners --reset --tran
python3 make_plots.py                         # results/fig5_postlayout.png
```

Results are in `results/postlayout.json` and `results/postlayout_combined.json` (summary in `design/README.md` §9). Two layout problems were found this way and fixed:

1. **Gain 0.56 dB too high.** The output trunk ran next to the non-inverting input over about 150 µm (8–12 fF). That is positive feedback of about 7 % of the C2 feedback. Fix: a vss shield track between the `inp` and `vout` metal3 trunks. Gain is now within 0.05 dB of the schematic and the bandwidth is back to the schematic value.
2. **PSRR at 50 Hz 77 dB instead of 96 dB (classic models).** The top input-pair row (an `inn` row) sat 1.5 µm from the M7 row, so `vdd` and `vbp` (which follows the supply) coupled onto `inn` only. Fix: 1.5 µm more space and a metal1 line on the tail node `t` between them. PSRR is now 86 dB (classic) and 90 dB (continuous models, 0.4 dB below the schematic) at tt / 27 °C, and 81–91 dB over corners. The rest of the difference is the drain-strap-over-gate coupling inside the input transistors, which is part of the device.

Two simulation details: the extracted netlist has a parent-level capacitor on a net inside the bias cell that is not a port, which leaves a node with no DC path; `tb_postlayout.py` removes it. And the output step when `rst` is released must be simulated with ≤ 2 µs steps (`--reset`); with 50 µs steps ngspice adds a false step of tens of mV.

## Step 6 — GDS, precheck, submission

1. GDS and LEF are written by `layout/blk_top.py` into `gds/` and `lef/`.
2. Every push runs the GitHub `gds` workflow (Tiny Tapeout precheck, then the viewer). It passes. The same precheck can be run locally with `tt-support-tools/precheck/precheck.py --gds <gds>`.
3. **Still to do (you):** check the datasheet text in `docs/info.md`, then go to app.tinytapeout.com, create the project for TTSKY26d from this repository (1x2 analog tile, 2 analog pins, €220) and submit **before 30 November**. Keep the repository public.
